# eduTasks

Express-приложение на порту 3000.

## Локальный запуск

```sh
npm ci
npm start
```

Для разработки с автоматическим перезапуском сервера при изменении исходников:

```sh
npm run dev
```

Команда использует встроенный режим `node --watch`: изменения в `src/app.js` и импортируемых модулях перезапускают сервер. Для остановки нажмите `Ctrl+C`.

## Docker

```sh
docker build -t edutasks:local .
docker run -d --name edutasks -p 3000:3000 --restart unless-stopped edutasks:local
```

Откройте http://localhost:3000/promise/.

## GitHub Actions → удалённый сервер

Требования: Linux с Bash, gzip и Docker Engine; архитектура x86_64 (образ собирается на ubuntu-latest). SSH-пользователь должен иметь доступ к Docker без sudo. Хост должен быть доступен по SSH из GitHub Actions. Порт приложения должен быть свободен и разрешён в firewall, если нужен доступ извне.

1. Добавьте публичную часть отдельного SSH-ключа в `~/.ssh/authorized_keys` пользователя сервера. Workflow использует только авторизацию по ключу, без пароля. Для автоматического запуска используйте отдельный ключ без passphrase; текущий workflow не разблокирует зашифрованные ключи.
2. В репозитории GitHub откройте **Settings → Secrets and variables → Actions** и добавьте repository secrets:

   | Secret | Значение |
   | --- | --- |
   | `SSH_HOST` | IP или домен сервера |
   | `SSH_USER` | Пользователь SSH |
   | `SSH_PORT` | Порт SSH; необязательно, по умолчанию 22 |
   | `SSH_PRIVATE_KEY` | Полный приватный ключ, включая BEGIN/END |
   | `SSH_KNOWN_HOSTS` | Проверенная запись сервера из known_hosts |

   Получить запись можно командой `ssh-keyscan -p 22 SERVER`, но перед сохранением нужно сверить fingerprint с сервером через доверенный канал. Для нестандартного SSH-порта используйте его и здесь.

3. При необходимости добавьте repository variable `APP_PORT` (по умолчанию `3000`). Контейнер всегда слушает 3000; эта переменная задаёт внешний порт сервера.
4. Отправьте код в ветку `master`.

Pull request запускает сборку и HTTP-проверки. Push в `master` или ручной запуск workflow для `master` после проверок передаёт Docker-образ по SSH и запускает контейнер `edutasks`. Registry и токен для него не нужны. Между остановкой старого и запуском нового контейнера будет короткий простой. При ошибке запуска или проверки здоровья старый контейнер восстанавливается.

Скрипт управляет контейнерами `edutasks` и `edutasks-previous`; используйте эти имена только для этого приложения. Если деплой был прерван и остался `edutasks-previous`, проверьте оба контейнера вручную перед следующим запуском. Старые Docker-образы автоматически не удаляются.

Проверка на сервере:

```sh
docker ps
docker logs edutasks
curl -i http://localhost:3000/promise/
```
